# 火种登录与加载验收（2026-10-17）

仅北京部署 `62.234.188.55`。本轮复用原生 Vue/TDesign、账号、目标、Wiki 与模型接口，没有迁移知识库，也没有调用模型生成课程或答案。

当前北京前端为 **fire-09**（首页与入口调整），冷启动优化结果见“本轮完成：fire-08”。前面的 fire-05/06 数据保留为历史基线，不代表当前版本。

## 原因与修复

- 匿名用户打开 `/` 时，先下载整个工作区，再进入独立登录页。Peter HTML 的前置登录跳转现在位于模块预加载之前；已有 token 继续走原生服务器校验，OIDC 回调、非工作区路径、不可用存储保留原流程。开发 `/login` 同步生产 nginx 的 302，避免初始化导航取消被当作页面失败。
- 火种 Logo 的红色被原登录页暗色 `invert(1)` 翻成绿色。Fire 专用规则取消 Logo 反色；眼睛等控件仍跟随实际主题。
- 生产知识库首页原本挂载隐藏的全套设置面板，连设置依赖也提前下载。改为复用 `uiStore.showSettingsModal` 与 Vue 异步组件，用户打开时才加载；独立设置路由仍由 RouterView 挂载。
- 原 Logo PNG 是 1284×1225、299126 字节，侧栏只显示几十像素。保留原图，另生成 256px（15867 字节）用于界面、64px（2379 字节）用于 favicon；形状和品牌不变。
- 浅色模式恢复原生白色 UI，黑红作为深色。设置、刷新、退出重登、跟随系统均验证，浏览器级登录外观不替代账号偏好。
- Wiki 页脚缺失的 `summary/UUID` 名称，复用 KB 范围的原生知识批量查询和已有来源标题缓存，一次去重取回中文名称，保留原 slug 跳转；其他未加载概念标题复用原生一跳邻接元数据（此页 1508 字节、6 个节点），不渲染图谱、不逐页请求，没有扫描全库或改写 Wiki 数据。

## 冷启动专项：官方按需与失败恢复

本轮按 Vue 官方代码拆分及腾讯 TDesign 官方按需导入方案处理实际首屏依赖，保留所有现有组件样式、本地图标、字体与权限。采用已安装版本的官方构建解析器；三个应用入口均移除全库组件注册，但显式保留 Dialog/Drawer/Loading/Message/Notify 五个服务插件及应用上下文。真实 Vite 构建元数据检查会在全量安装器重新进入任何入口时失败。

关闭的 Markdown 编辑器及检索设置不进入知识库首页下载。Markdown 编辑器仍复用冻结的原控制器；只补延迟首次挂载时的原生初始化，不另写编辑/保存逻辑。生产预览已实测当前知识库绑定、首次标题、Markdown 预览、取消和再次打开，未保存测试内容。

身份恢复仍先于应用挂载。Edition 与 capabilities 只在身份及租户前提满足时并行，全部结束后才执行原有门禁；带旧租户覆盖的 Lite 校正保留串行，无有效租户先转引导，避免为并行而提前发送受租户保护请求。

HTML 内联加载区在应用 JS 到达前显示当前主题和红色小 Logo。10 秒仍未结束只是继续加载；断网和真实脚本失败分别提示，重试由用户点击，不自动刷新，也不显示虚构百分比。

合并审查额外发现：新延迟编辑器首次下载失败可能静默挂起。Chrome 故障注入证明，同 URL 动态 import 第二次仍失败且没有新的资源请求，改查询串才成功。因此使用现有原生 Dialog 提供明确刷新恢复，并可取消当前入口；不把重复同一 import 当作有效恢复。三处真实延迟消费者共用一个小工具，不新增产品 UI 或独立状态存储。故障取消后再打开也必须仍有恢复入口。
