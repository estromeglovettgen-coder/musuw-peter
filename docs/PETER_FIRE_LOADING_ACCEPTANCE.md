# 火种登录与加载验收（2026-10-17）

仅北京部署 `62.234.188.55`。本轮复用原生 Vue/TDesign、账号、目标、Wiki 与模型接口，没有迁移知识库，也没有调用模型生成课程或答案。

## 原因与修复

- 匿名用户打开 `/` 时，先下载整个工作区，再进入独立登录页。Peter HTML 的前置登录跳转现在位于模块预加载之前；已有 token 继续走原生服务器校验，OIDC 回调、非工作区路径、不可用存储保留原流程。开发 `/login` 同步生产 nginx 的 302，避免初始化导航取消被当作页面失败。
- 火种 Logo 的红色被原登录页暗色 `invert(1)` 翻成绿色。Fire 专用规则取消 Logo 反色；眼睛等控件仍跟随实际主题。
- 生产知识库首页原本挂载隐藏的全套设置面板，连设置依赖也提前下载。改为复用 `uiStore.showSettingsModal` 与 Vue 异步组件，用户打开时才加载；独立设置路由仍由 RouterView 挂载。
- 原 Logo PNG 是 1284×1225、299126 字节，侧栏只显示几十像素。保留原图，另生成 256px（15867 字节）用于界面、64px（2379 字节）用于 favicon；形状和品牌不变。
- 浅色模式恢复原生白色 UI，黑红作为深色。设置、刷新、退出重登、跟随系统均验证，浏览器级登录外观不替代账号偏好。
- Wiki 页脚缺失的 `summary/UUID` 名称，复用 KB 范围的原生知识批量查询和已有来源标题缓存，一次去重取回中文名称，保留原 slug 跳转；其他未加载概念标题复用原生一跳邻接元数据（此页 1508 字节、6 个节点），不渲染图谱、不逐页请求，没有扫描全库或改写 Wiki 数据。

## 实测方法与结果

Chrome 新上下文、390×844 手机视口、真实 HTTPS、真实账号 API、关闭缓存的加载瀑布；本机目标 IP 从 TUN 排除，并加入系统代理绕过，实际路由为 en0。公网入口直接到北京 nginx，没有通过 Cloudflare。以下是本机到服务器的实测，不能代表用户手机每条运营商链路。

| 阶段 | 改前 | 改后 |
| --- | ---: | ---: |
| 知识库卡片出现 | 9.592 秒 | 6.001 / 6.112 / 6.047 秒 |
| 截至卡片出现的传输量 | 3.14MB | 约 2.23–2.30MB |
| 改前 HTML 首包（含连接） | 约 0.115 秒 | 无需用健康接口代替整页计时 |
| 改前主线程长任务合计 | 134ms | 最后复测 144ms |
| 未打开设置时的 Settings 页面模块 | 已下载 | 未下载；点击设置后正常加载 |

匿名首页前置跳转发布后的首轮同条件测量从约 1.63MB 降至 0.21MB；该轮登录框出现约 2 秒，随后资源进一步使用小尺寸 Logo。最终常规刷新有缓存时，知识库约 0.44–0.46 秒；历史对话约 0.58–0.91 秒，另有一次约 4.71 秒长尾，不能抹去或描述为始终秒开。

同一个压缩后 857765 字节 JS：服务器 HTTPS 回环 0.105 秒；公网直连两次 1.891 / 2.115 秒（约 0.41–0.45MB/s）。服务器内部真实 `/auth/me`、系统信息、能力、知识库列表和历史会话接口分别约 2.70、2.10、1.89、4.73、3.14ms。负载约 0.03，应用 CPU 约 0.46%，可用内存约 2GiB；没有当前 CPU 满载或数据库数秒计算的证据。

因此剩余等待主要在公网传输和仍需加载的基础界面资源。完整最终复测仍有 8.291 秒冷启动；6 秒不是稳定承诺。冷启动仍偏慢，不能宣称已完全消除卡顿。腾讯云控制台登录已过期，用户暂不方便登录，套餐带宽上限尚未核实；不把实测吞吐直接当成配置限速，也未擅自付费升级。保留中文字体及原生编辑/Skills/沙箱权限。
