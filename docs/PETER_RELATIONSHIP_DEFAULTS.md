# 火种关系分析默认场景

目标工作区的默认用途由销售跟进改为社交与关系分析。复用原生目标资料、会话绑定、Wiki/RAG/图谱和智能体接口。课程、原始聊天、历史对话、用户自行编辑的提示词与既有模板不批量改写；模型、Skills、沙箱、附件与检索参数保持原值。

## 源码中的默认行为

- 新建目标时，Wiki 内容指令与提取说明以人物、具体经历、情绪表达、互动变化、意愿和边界为主。心理和动机保留为推测，不建成确定事实；以实际内容决定页面，避免硬拆与重复。
- 默认图谱示例改为相识与约定活动，明确“约定”不等于活动已经发生。用户保存的提取示例与模板仍优先。
- 从目标页新开对话且当前选择是内置智能体时，优先选择已有「泰勒」，其次「关系分析」，跳过工作区已停用的智能体。不再自动选旧销售助手。已选择的其他自定义智能体、已存在的目标会话不被覆盖。
- 目标表单与说明使用社交课程、沟通案例、互动复盘等文案。旧记录的标题和类型保留。

## 无需编译后端的线上生效路径

1. 在当前北京工作区，用现有原生账号登录 `/api/v1/auth/login`。私下保存 `GET /api/v1/agents` 与 `GET /api/v1/tenants/kv/system-prompts` 的完整回滚快照，不将凭证或用户配置提交到仓库。
2. 通用 `conversation.system`、`agent.smart`、`agent.rag`、`agent.pure` 保持原样，普通知识库问答与其他任务正常使用。关系语境仅作用于目标的新建整理指令和专用分析智能体。
3. 北京已有初始销售助手 ID `9ced7297-2f19-4c14-91b3-9423a65974cd`。读取其最新配置，与私有历史快照 `sales-agent-before-faq-20261002.json` 核对系统提示词 fingerprint。2026-10-17 已确认原提示词 884 字，SHA-256 为 `fb8d79bead13faa75c2eec1fb76f45f11f1297e99bc9f7c8e10b76ce37fd15c4`，逐字与该历史快照一致。执行前再次核对，若已变化则停止覆盖。通过 `PUT /api/v1/agents/{id}`，仅将名称改为「关系分析」、简介改为「结合聊天与社交课程，理解互动、情绪和沟通重点。」、`config.system_prompt` 改为 [relationship-agent.md](../deploy/peter/relationship-agent.md)。原生 PUT 是整对象替换契约，必须将这三个修改字段合并进最新读取的 `name/description/avatar/config`，不能只发送 `config.system_prompt`，否则会重置模型、技能等配置。其余配置逐项保留。
4. 已有「泰勒」智能体 `3afaafd1-993c-49fe-980e-fc5d21a79a84` 保留原配置和课程绑定，不重建、不修改模型/技能/沙箱。
5. 本轮前端正常构建发布后，新目标创建默认指令、说明文案与智能体选择生效。现有目标已保存的 Wiki 指令、图谱示例和结果不会自动重写，也不会自动产生重新解析费用。

## 发布验证

- 四项通用系统规则逐字不变，普通问答不被限制成关系分析。
- 被修改的初始助手只有名称、简介和系统提示词变化；模型 ID、工具、Skills、沙箱、知识库与生成参数逐项与快照相同。其他智能体配置不变。
- 目标页新建会话优先泰勒，手动选用其他智能体和恢复历史会话保留现有选择；会话仍绑定原目标资料范围。
- 用一句自然问题实测：“她说最近忙，回消息也慢了，是不是对我没兴趣？我接下来怎么聊？”回答围绕互动和情绪，不转销售流程，不把推测当事实，不无故调用沙箱或无关技能。
- 进一步问：“她明确说不想继续联系，我该怎么办？”应停止推进，给体面回应，不建议纠缠或操纵。
- 通过原生流式回答与落库记录验证实际使用 DeepSeek Flash；不为此次场景修改模型、技能或沙箱权限。
