动画图片只取静态画面；RAW、PSD、PDF 和多页 TIFF 不冒称单张图片完整支持。Safari/手机实机的系统文件选择、下载与 HEIC 解码仍需真机观察，Chrome 响应式测试不能替代所有真机。

## 根因与改动

1. 原 JPG 校验依赖浏览器 MIME；现在先识别文件头，只有确实不兼容时转换。
2. 首次 host/bootstrap/config 重复握手；现在唯一 config 的身份、租户及实时额度由原生后端覆盖，不信任侧车自报身份。
3. Python 3.11 HTTP 服务默认 listen backlog 为 5，并发下载会出现 TCP 连接重试。生产同版 Python 旧实现 16 并发有约 1.3 秒长尾，改为 128 后同一回归通过。
4. 主页主共享包混入四种完整语言；保留中文 fallback，其它按当前语言读取，并发复用同一个加载，切换完成再保存偏好，失败保留原语言。
5. 首屏同步请求全量 2347 个图标；从原版 TDesign 提取实际使用的 228 个符号，79KB 原文/约 13KB gzip，其余动态图标有同源完整表兜底。与语言分离合计减少约 520KB 首屏压缩资源。
6. config 与小图标必须先于主程序执行，现在在 head 优先发现，原脚本执行顺序不变；真实浏览器验证两个资源均只请求一次。

## 质量和运行限制

第一张默认提示词没有严格遵从穿搭，不能把“返回图片”描述成所有参考都准确还原。第二张用简短明确描述后符合本次四图组合，保留了原项目自由创作能力；模型对细节仍有随机性。

生成已成功，但不是秒出。第二次任务从创建到保存约 94 秒，其中供应商记录 56 秒，其余包含原图上传与结果传输。测试电脑到北京上传 10.8MB 原图曾耗约 4 分钟，单张 2.2MB 结果浏览器传输曾约 26 秒；这属于实际链路限制，不能称为国内所有用户的速度。未通过压缩用户原图改变原项目行为。

图片预占未知不会自动超时释放或重新生成，避免重复计费。管理员可在原生用户套餐中核实并处理；新老套餐的图片额度默认 0，需明确配置后赠送，0 不代表无限。
