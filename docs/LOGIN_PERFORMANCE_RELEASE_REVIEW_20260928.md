本次范围为新登录回调与旧会话校验的执行顺序、启动反馈、非关键前端资源加载，
以及不包含用户正文或凭证的阶段诊断和已有应用日志的有界保存。
不修改权限规则、付费规则、模型选择或用户数据结构，不调用支付或模型服务。

候选及 staging run 只能在下列验收完成后登记，登记时同步填写实际证据与未完成项：

- [ ] 原有 CI、构建、类型检查、来源与发布契约通过。
- [ ] 新 OIDC 回调优先于旧 token 预检；普通访问仍校验会话；暂时网络失败不会冒充凭证失效。
- [ ] 移动端慢速加载时立即显示启动反馈；成功移除占位；失败保持可恢复入口。
- [ ] 真实构建的首次依赖图及浏览器请求证明非必要的大资源已延后，相关功能首次打开仍正常。
- [ ] 诊断仅接收允许的阶段、耗时和错误类别；拒绝额外字段、超限和无效输入；不收集正文、验证码或 token。
- [ ] 测试环境使用与候选 artifact 相同的 app/frontend digest；健康、隔离及现有容量检查通过。
- [ ] 应用日志使用独立私有卷；以实际 appuser 可写；容器更换后仍保留；复用 50 MB、3 个备份、28 天和压缩规则。
- [ ] 汇总一次独立审查，修复当前阻塞，记录真实设备/国内网络尚未覆盖的限制。

完整 Paddle Sandbox 生命周期不在本次验收范围，禁止填写 `full-sandbox-e2e-green`。
未完成的验收不得写成已通过。

晋级仍必须核对完整 SHA、canonical main 祖先、成功 CI、此前 staging artifact、
在线 staging digest、当前正式环境成功 manifest，以及 `server-production` required reviewer。
保持原有失败回滚与健康检查，复用已验收镜像，不在服务器构建或改用可变标签。

这份公开源码记录仅保存版本、检查类型和结果，不包含账号、真实日志、IP、密钥或内部请求内容。
