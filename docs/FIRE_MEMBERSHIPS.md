# 火种账号与 Token 套餐

本功能只在北京私有火种部署启用。原生 Musuw 的金额额度、支付服务、原有课程内容不参与这套账本。

## 日常操作

系统管理员通过 `/platform/manage` 创建套餐、开户、检索账号和调整额度；普通用户通过左下角查看套餐、到期时间和剩余 Token，`/platform/usage` 查看明细。网页导入入口隐藏，文件、文件夹和手动录入保留。

北京地址：`https://62.234.188.55/platform/manage`，使用现有 Peter 管理员账号登录。上线时准备了可编辑的“标准套餐”：30 天、总计 1,000,000 Token；它只是人工发放的默认模板，没有自动续订、支付或信用卡扣款。

首次开户：点“新建账号”→选择套餐→创建并复制一次性显示的账号密码。用户名／密码留空即可自动生成，也可以自定义。交付用户登录地址 `https://62.234.188.55/auth/start`；用户可以直接输入用户名，不需要真实邮箱。后续从用户详情调整会员、查看明细或重置密码。

- 套餐是 N 天内的总 Token，不按次数、天或金额扣减。管理员发放后立即生效。
- 默认用户名 `taylor001` 顺序递增；默认密码为 `Ty` 加六位密码学随机数字，每个人不同，也可自定义。密码只在创建成功时展示一次，不保存明文。
- 开户操作有唯一操作 ID；相同输入重试只返回原账号，不再次发额度或展示旧密码。如果响应丢失，进入用户详情的原生“重置密码”恢复。重置会撤销该用户已有登录会话。
- 套餐模板以后编辑或停用，不追溯修改已发放的套餐。开户可覆盖模板天数和额度。
- 未到期续费：原到期时间顺延，剩余额度累计。过期续费：从现在重新开始，不恢复过期额度。
- 追加额度仅加 Token，不延长有效期；赠送天数仅加时间。过期后只追加 Token 仍不能调用模型，需续费或赠送天数。
- 暂停独立于到期／余额，续费和充值不会偷偷解除暂停。暂停、过期或余额不足仍可登录、阅读历史。
- 管理员身份不需要套餐。现有非管理员不会被自动赠送额度；管理员可在后台明确发放，避免意外的无限免费调用。

## 默认资源与隔离

每个新账号拥有独立的原生个人租户与 Owner 身份。本地 `fire-taylor` 为受保护的默认泰勒投影，共享课程走原生组织 viewer 分享；不会复制课程全文、源 API 密钥、私有 MCP 或沙箱凭据。用户不能修改、删除公共课程和默认投影，可创建自己的智能体或复制后调整。

首页保留原生智能体选择和思考深度，隐藏模型名称及选模视图。所有新对话已选泰勒，并引用授权课程；历史对话保留其原来的上下文。用户自己的目标、文件、记忆和会话仍受原生权限隔离。沙箱用会话绑定的 Docker 后端，Skills 保留，不使用宿主机直接执行模式。

## 计量规则

所有原生模型 HTTP 出口统一计量，包括对话、标题／改写、摘要、Wiki、图谱、附件、向量、重排、语音与视觉。先原子预留、再幂等结算；并发不会重复占用同一余额。

优先采用供应商返回的输入＋输出 Token，缓存是输入的子集，思考是输出的子集，不重复相加。TEI 的 `x-compute-tokens` 可直接计量。供应商未返回 Token 时，用现有 BPE 编码器计算文本估算量，明细标注“估算”。图片／音视频在缺少供应商统计时，文本估算不能等同于媒体内部真实 Token。

网络请求未成功发出或供应商明确拒绝且无用量时释放预留。发出后中断、掉线或进程重启导致最终用量不可知时，按预留上限保守估算并明确标记，管理员可追加额度补偿。超时遗留预留由恢复器结算，避免永久锁住余额。已开始的调用可以在到期后完成；供应商实报若超出估算，保留完整用量，剩余归零并禁止后续调用，不篡改历史。周期重置前必须结清在途调用。

管理员维护凭真实管理员身份免扣，不因为资源属于普通用户就扣该用户。原生异步任务保留真实发起人；Wiki 混批按发起人分组；平台机器身份只存 key ID，并在异步计量时重查当前有效性和授权，不保存密钥或永久权限副本。维护时不能用普通用户的登录身份冒充管理员。

## 开关与发布

显式配置 `PETER_TOKEN_BILLING_ENABLED=true`、`FIRE_SOURCE_TENANT_ID`、`FIRE_COURSE_KB_ID`、`FIRE_TAYLOR_AGENT_ID`。同时启用原生 `WEKNORA_SANDBOX_MODE=docker` 与已验证的 Docker 基础镜像；不得把源租户的环境变量、私有技能快照或凭据复制到新用户。

本次新增 PostgreSQL 112/113 与 SQLite 31/32，全部增量建表，生产不使用 AutoMigrate。先保存数据库及配置快照，再部署镜像，由原生 migrator 应用迁移。保留旧镜像、前端发布目录和运行时 config.js。

回退不能删除账本或恢复旧快照覆盖用户后续数据。紧急后台回退先暂停模型写入口，再使用保留旧二进制、包含新迁移文件的兼容回退镜像；这样旧 migrator 能识别当前版本，新增数据仍保留。正常修复优先向前发布；前端支持独立原子回退。私有凭据、原始 SSE、数据库快照和完整发布日志均留在忽略的 `.runtime/`，不提交 Git。
