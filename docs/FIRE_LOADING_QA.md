# 套餐和展示面加载优化（2026-10-20）

范围：北京火种的普通用户套餐、管理员套餐列表、展示工作台打开与返回。保留课程、聊天、计费、图片供应商、原图上传和已有提示词配置；本轮不调用付费生成。

## 原因与基线

- 实际浏览器从知识库进入展示面耗时 12,341ms，另一次接近 20 秒超时。
- 对齐这两次请求的原生服务日志，bootstrap 处理分别为 1.833ms、1.839ms。独立五轮测量：普通套餐服务端中位 2.71ms，浏览器外直连 TLS 请求中位 162.9ms；bootstrap 服务端中位 2.85ms、直连中位 146ms。不是数据库查询耗时十几秒。
- 父页先 bootstrap，子页再 bootstrap，四个脚本串行请求；所有公开脚本/样式均 `no-store`，切换路由又销毁 iframe。
- 隐藏的旧品牌图仍进入浏览器下载队列，660KB 的非必要资源会竞争带宽。
- 普通套餐已有 30 秒内存缓存和在途请求合并，但首次点击才读取。管理员用 `Promise.all` 等概览后才发布已返回的套餐，重复点击刷新可发多组请求。

## 实现

- 已认证工作区后台预取普通套餐；只在头像菜单显示原有百分比 UI。强制用量更新发新请求，旧结果不能覆盖；账号或租户变化清空快照。服务器实时扣额逻辑不变。
- 管理员套餐、概览独立展示加载、错误和结果；合并重复刷新，创建或调整后强制读取新结果；加载失败不伪装成空列表。
- 工作台在原生 DOM 中保持同一个 iframe，空闲时低优先级预热；普通切页不销毁草稿。切换账号、租户或退出立即销毁旧文档。
- 子工作台独立完成唯一鉴权启动，公开脚本预载并行下载，仍按既有依赖顺序执行。移除隐藏旧品牌图的下载地址。
- 公共资源按内容版本缓存，强 ETag 支持弱 `If-None-Match` 的 GET/HEAD 条件请求；只有受信任公共静态文件成功响应可缓存。HTML、配置、任务、私图和错误保留 `no-store`。
- 隐藏停止任务轮询，返回刷新任务和图片额度；不重新初始化历史或触发生成。401/403、身份失效关闭旧工作台；临时网络错误保留草稿、暂停生成并诚实显示额度暂不可读，恢复后重新可用。

## 本地验证

- Vue 真实 DOM：23 个不同用例通过，包含预取、并发旧回执、套餐独立加载、重试、开户与调整、持久草稿、用户/租户/退出隔离、伪造消息、401/403/503、20 秒超时和慢原图不阻塞可用。
- 整合后 Vue 类型检查与生产构建通过；保留现存大 chunk 提示。
- 最终 Python 83 项、原生 host 与实际工作台脚本 32 项通过。另有 Chromium 原始四脚本和 HTTP 完整启动、隐藏恢复测试，零生成 POST；脚本并行提前下载、执行顺序不变、隐藏品牌图零请求。
- Go 全 handler 包与 FireShowcase handler/router 定向测试通过，覆盖 GET/HEAD/304、公共策略白名单、私人 API/图片、错误和越权路径。全 router 包中既有 Paddle 源码字符串断言失败：测试仍查 `r.Use(middleware.Auth(`，HEAD 已改为复用 `nativeAuth`；与本轮两文件修改无关，真实授权回归通过，未修改支付代码。
- 合并对抗审查发现并修复了普通预取吞用量更新、弱 ETag、持久页面返回时鉴权失效三个实际边界；对应纠正测试通过。

## 生产验收

同一台电脑的线上内置浏览器实测：

| 场景 | 实际结果 |
| --- | --- |
| 展示面日常切回 | 原基线 12,341ms；新版本 396ms |
| 已登录普通用户，空闲预热后点击展示面 | 84ms；0 张额度、0 张参考图，未出现管理员状态 |
| 普通用户点头像读取套餐 | 458ms，显示标准套餐、100% 百分比；首次引导关闭后测量 |
| 切页后的文档与草稿 | 草稿保留；切回期间工作台文档导航 0 次 |
| 公共资源真实缓存 | 8 个版本化脚本/样式全部内存缓存命中，传输 0 字节；条件 GET/HEAD 为 304，旧版本走 `no-cache` 重新校验 |
| 普通套餐接口，五轮独立直连 | 中位 144.61ms，最大 240.99ms；服务端中位 2.72ms |
| 套餐目录接口，五轮独立直连 | 中位 142.21ms，最大 290.36ms；服务端中位 2.54ms |
| 线上 HTTP 契约 | 8 个公共资源和 8 项私人/错误/匿名检查通过；HTML 实时，私有接口及图片不进入公共缓存 |

冷加载与强制重开仍有网络长尾，不能宣称所有首次都一秒：首次新工作台从其 HTML 请求到首个任务列表响应的网络阶段约 4,109ms；整页首次导航超过浏览器工具的 10 秒导航等待，随后实际页面正常可用。一次明确点击“重新加载”的 UI 耗时 9,034ms，其中 config 请求在浏览器侧等待 5,646ms，对齐原生服务日志为 3.544904ms。已命中缓存的脚本并未重新下载，长尾发生在客户端链路；本轮通过预热和保活避免日常切页反复承受这次重开，但没有声称消除外部网络波动。

验收使用现有普通演示账号，未创建/删除用户，未调用供应商生成；结束后恢复原管理员会话并清空验收草稿。浏览器原始日志与普通用户截图保留在忽略的 `.runtime/peter/latency-20261020/`；可提交的脱敏指标在 `artifacts/fire-loading-20261020/metrics.json`。
