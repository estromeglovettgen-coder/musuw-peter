# Taylor 默认对话

范围是北京火种定制工作区。保留 Peter 的技术标识、账号和存储路径；仅调整提示词身份、默认新对话选择与设置可见性。课程原文、Wiki、图谱和向量索引不重新生成。

## 行为

- 全局新对话从本账号原生智能体列表解析启用的自建「泰勒」，迁移旧内置智能体默认。通过原生选择动作同步其模型、课程库和工具，用户无需先 @ 知识库。
- 保留明确选择的其他自建智能体、共享入口、嵌入式对话及历史会话绑定。首发等待智能体资源就绪；加载失败显示错误，不能静默使用内置智能体。等待中离开页面不继续发送，并发首发只提交一次。
- 人设采用 `deploy/peter/taylor-agent.md`，根据课程判断方式和表达习惯交流，保留事实检索、原文核对及真实引用。第一人称讲课不等于真人实时回复；其他讲师的经历不归到 Taylor 身上。
- 原生系统提示词和模式预设的身份统一为 Taylor。已有用户自定义内容只替换旧身份，保留变量和其他规则。自建泰勒仅更新 `config.system_prompt`，模型、知识库、Skills、工具、MCP、沙箱等配置保持原值。
- 设置侧栏隐藏「系统提示词」，旧深链回到常规设置。后台 API 与智能体编辑能力保持原有授权。

## 发布与回滚

前端使用正式 Peter 构建并原子切换版本，保留 `config.js` 和旧静态资源。原生提示模板由 ConfigLoader 启动时读取，使用 `deploy/peter/Dockerfile.prompt-templates` 在当前已验证运行镜像上叠加四个 YAML 文件；不重编译二进制、不升级依赖，也不调整其他服务。

部署前将原镜像、Compose 环境、容器设置、系统提示词与泰勒配置保存到私有 `.runtime/peter/taylor-persona-20261017/` 和服务器受限交付目录。比较环境变量与挂载时忽略 Docker Compose 输出的列表顺序，内容、权限和资源上限必须一致。失败恢复旧镜像与提示词配置；前端独立恢复旧版本软链接。
