# 第一版视频导入与解析计划

## 定案

第一版只使用一个已经接入、成本较低、支持视频 URL 的模型处理视频。
产品侧统一支持最大 300 MB，不做多模型选择、自动路由、价格计算或能力矩阵。

用户界面不展示底层模型、视频来源服务、模型网关、对象存储、解析器或供应商名称，
只表达 Musuw 的产品能力：`视频解析，最大 300 MB`。

## 目标

- 一个视频最多获取并保存一次。
- 视频解析失败后保留原文件。
- 重新解析只读取已经保存的原文件，不重新解析分享链接、不重新下载、不重复存储。
- 对可恢复的临时错误使用同一个模型自动重试一次。
- 错误信息准确说明“来源获取失败”“视频超过 300 MB”或“视频解析失败”，不再统一显示为文档解析失败。
- 继续使用现有 WeKnora、私有对象存储、预签名上传和任务队列，不增加新服务。

## 最小链路

### 本地上传

```text
选择视频 -> 浏览器检查不超过 300 MB -> 现有上传链路保存原文件
        -> 固定视频模型解析 -> 完成或保留原文件等待重试
```

大文件继续使用现有浏览器直传和 multipart；不要改造上传协议。

### 分享链接

```text
提交链接 -> 查找已有来源 -> 未命中时解析链接一次
        -> 检查/流式计算真实大小 -> 不超过 300 MB 时保存一次
        -> 固定视频模型解析 -> 完成或保留原文件等待重试
```

- 在调用外部来源服务前，先按租户和规范化后的原始链接查找已有且健康的存储对象。
- 第一次解析成功后保存稳定内容标识或规范化链接，后续提交优先复用。
- 第三方下载 URL 会过期，不能作为重新解析的数据源；私有存储中的原文件才是数据源。
- 如果来源明确超过 300 MB，不继续下载或调用模型；若响应没有可靠大小，则流式读取到上限加一个字节后停止并清理未完成对象。

## 固定模型

内部固定使用现有 `builtin-openrouter-vlm-qwen-3-7-flash` 配置，但这个内部名称以及它的网关、
路由和供应商信息不能出现在终端用户界面或公开错误中。

实现时优先复用现有知识库模型解析和视频 URL 输入代码。允许用一个服务端配置覆盖默认模型，
便于紧急回滚，但不要建设模型候选列表、模型评分器或用户视频模型选择器。

固定模型的能力边界：

- 通过短期 HTTP(S) URL 读取视频；
- 原文件最大 300,000,000 字节；
- Base64 只作为已有小文件兼容路径，不用于接近上限的视频；
- 支持格式仍需沿用现有产品白名单和真实端到端测试结果。

## 保存与重新解析

来源保存成功和模型解析成功是两个不同结果，但第一版可以继续使用现有知识记录、文件路径和
任务状态表达，不为此新建通用资产系统。

重新解析接口必须以现有知识记录和文件路径为入口：

1. 检查租户和知识库权限；
2. 确认原文件仍存在且大小不超过 300 MB；
3. 为同一个对象生成新的短期读取 URL；
4. 再次调用固定模型；
5. 不进入分享链接解析或下载逻辑。

如果用户再次提交完全相同的规范化链接，已有健康原文件应直接复用，不能创建第二份对象。

## 重试

只对明确可恢复的情况自动重试一次，例如临时网络错误、限流、服务端错误或合法响应中没有
可用文本。永久参数错误、格式不支持和超过 300 MB 不重试。

重试始终复用已经保存的原文件。内部日志保留真实状态码、响应原因、模型和路由信息；公开
状态只显示安全、可理解的产品文案。

## 用户界面文案

第一版移除或隐藏视频模型选择动作，只显示：

- `视频解析，最大 300 MB`
- `原视频已保存，正在解析`
- `视频解析暂时没有得到结果，正在重试`
- `视频解析失败，原视频已保存，可以重新解析`
- `视频超过 300 MB，当前版本暂不支持`
- `视频来源获取失败，请稍后重试`

终端用户界面和公开 API 错误不得出现：

- 视频来源服务商名称；
- 模型网关、底层供应商或路由名称；
- 云服务、对象存储或协议厂商名称；
- 内部解析器、任务队列或内部错误标识。

用户界面不能直接显示上游响应正文。管理端、服务端日志和追踪必须保留完整诊断信息。

## 实施顺序

1. 核对当前视频入口、分享链接、保存、解析、重新解析与失败状态的真实调用链路。
2. 将视频解析固定到一个服务端配置，并移除第一版无意义的视频模型选择入口。
3. 确保分享链接解析成功后原文件只保存一次，解析重试直接复用现有文件。
4. 为相同租户的相同规范化链接增加最小复用检查，优先使用现有字段和索引。
5. 将 300 MB 校验统一为后端权威值，前端只读取安全能力信息或共享运行时配置。
6. 增加一次同模型可恢复重试，并拆分准确的公开错误状态。
7. 审计所有相关终端用户文案，清除服务商和内部组件名称。
8. 用真实的小视频、接近上限的视频和已保存的分享视频验证首次导入、失败、重试、重新解析和重复链接。

## 验收

- 300 MB 内的本地视频和分享视频能够使用同一个固定模型完成解析。
- 视频超过 300 MB 时，在模型调用前停止并显示准确提示。
- 模型返回空结果或临时错误时只自动重试一次，不重新调用分享链接服务。
- 点击“重新解析”不会增加存储对象数量，也不会重新下载来源视频。
- 再次提交同一个规范化链接时，已有健康对象被复用。
- 失败任务仍可查看或删除已经保存的原文件。
- 用户可见页面、通知、处理时间线和公开错误中没有服务商或内部系统名称。
- 服务端日志仍能定位实际失败阶段和上游原因。

## 明确不做

- 多模型自动路由和模型能力表；
- 用户视频模型选择器；
- 动态价格或成本估算；
- 第二套对象存储或视频平台；
- Worker 文件代理、tus 或新的上传服务；
- 自研播放器；
- 重写 DocReader；
- 普通文档的大文件 URL 拉取改造；
- 新的通用资产、工作流或编排框架。
