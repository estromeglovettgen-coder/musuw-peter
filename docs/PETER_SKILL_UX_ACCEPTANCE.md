# Peter 技能操作简化与验收

## 用户流程

1. 在「设置 → 技能」粘贴技能来源链接，或上传含 `SKILL.md` 的 ZIP，核对识别结果并安装。
2. 等技能显示就绪。在「智能体 → 编辑 → 技能」选择「全部」「指定」或「禁用」；选择「指定」时勾选要用的技能并保存。
3. 新建会话并提出需要该技能处理的任务。技能所声明的外部服务凭据仅在需要时于技能管理页填写。

Peter 当前空间只有一份具名运行沙箱。界面自动使用它，仍将其 ID 保存到启用技能的智能体配置；安装目标和安装模型的选择控件不再要求 Peter 操作。服务端安装器已有按工作区默认可用对话模型回退的逻辑；前端不再因为安装器未单独指定模型而阻断安装。其他工作区仍保留多沙箱选择和安装模型控件。

## 线上整链路复验

新版前端部署后，在本仓库根目录运行：

```sh
PETER_ACCEPTANCE_ORIGIN=https://62.234.188.55 node e2e/peter/server-skill-ux.mjs
```

脚本使用忽略版本控制的演示账号，复制一位演示智能体作为临时对象，经过浏览器勾选 `customer-report`，通过 API 核对保存的技能范围与沙箱绑定；随后上传虚构 CSV，要求智能体执行技能生成文件，下载并核对文件内容，最后清理临时会话与智能体。结果保存在忽略目录 `.runtime/peter/deployment/skill-ui-acceptance.json`。正式 Peter 主空间的数据和模型配置不受脚本修改。

恢复三种选择模式后，脚本已同步为先选「指定」再勾选；本次按用户要求不执行线上验收，由用户验收。

2026-09-30 新版前后端发布后已运行该脚本：浏览器技能目录和智能体技能页正常显示，隐藏沙箱设置；勾选 `customer-report` 后，服务端读回「指定技能」及当前工作区唯一沙箱 ID。上传虚构 CSV 后，技能在沙箱中实际生成一个文件，下载内容核对为 3 位客户、12 次跟进，临时会话与智能体已清理。原始检查结果保存在 `.runtime/peter/deployment/skill-ui-acceptance.json`。
