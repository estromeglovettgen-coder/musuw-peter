## Context

现有空间 KV 接口已经有管理员写权限，HTTP 请求和解析任务通过 TenantInfo 携带空间配置。模板分布在 YAML 默认配置及 Wiki/记忆等运行时常量中。

## Goals / Non-Goals

目标：单一中文目录、保存和恢复、空间隔离、真实调用生效、内容范围不被默认长度覆盖。
非目标：新建提示词平台、重写客户资料、改变结构输出字段、翻译用户上传资料或第三方技能内容。

## Decisions

- 复用 Tenant 增加 JSON 提示词覆盖值，复用原生 KV 权限，单条保存原子更新避免覆盖其它条目。
- 目录列出真正接通的模板；只有自然语言正文可编辑，变量提供提示并验证语法与必需的数据输入变量。
- 请求按空间配置解析，后台 Wiki 工作重新加载 TenantInfo，已有智能体自定义仍优先；不修改进程共享配置。
- 内容要求控制广度和长度；引用、真实性及 JSON/Markdown 协议继续有效。文件摘要读取同一知识库内容要求。

## Risks / Trade-offs

- 过度删除模板数据变量 → 保存时拒绝缺少必需输入的模板。
- 修改模板无法反向改变已有生成结果 → 界面明确提示重生成。
- 模型输出并非确定性 → 离线请求捕获验证配置传递，辅以有界真实模型生成验证。

## Migration Plan

新增可空 JSON 列；旧版本和未配置空间保持默认。发布先运行迁移再更新后端和前端，可回滚程序保留覆盖值。
