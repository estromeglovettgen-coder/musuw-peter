# Musuw Lite 上线前 UI 与新手引导收口需求

## 1. 目标与原则

本次目标是让单用户、单租区的 Lite 用户首次进入 Musuw 后，能够顺畅完成“创建知识库 → 添加资料 → 发起对话”，并让设置、知识库、智能体、账号菜单和记忆页面使用同一套现有 Musuw 视觉语言。

实现遵循以下原则：

- 以 WeKnora 已有源码、Driver.js、TDesign 和 Musuw 现有样式为基础，不引入第二套组件系统。
- 常规设置中的成熟下拉框是唯一权威；通过现有共享类机械复用，不逐页自研。
- 主页新对话输入区的 DOM、布局、颜色、字号、间距和交互全部保持不变，只允许添加不影响 UI 的引导定位属性。
- 不修改 API、数据库、支付、权限、套餐、额度、存储、多租户、共享或沙箱业务逻辑。
- Standard 版原有成员、空间和教程重放能力保留；Lite 只隐藏不可用入口和不准确话术。

## 2. 详细需求与验收标准

### 2.1 空知识库首次引导

- 空列表时必须高亮页面中间的“新建知识库”，不能误高亮右上角按钮。
- 引导卡片在当前视口内完整显示，不被边缘裁切。
- 非空列表没有中间按钮时，才允许回退到右上角“新建知识库”。
- 最后一步高亮现有“创建”按钮，并允许用户直接点击完成。

### 2.2 默认名称与序号

- Lite 新建知识库默认填入本地化的“我的知识库”。
- Lite 新建自定义智能体默认填入本地化的“我的智能体”。
- 同名存在时取第一个空缺序号，从 2 开始。例如已存在“我的知识库”和“我的知识库（2）”，默认使用“我的知识库（3）”；如果（2）空缺，则优先使用（2）。
- 默认名称可编辑；仅依据前端已加载列表给出建议，服务端原有校验仍是最终权威。
- Standard 和带有既定名称的智能体预设保持原逻辑。

### 2.3 知识库内部引导

- “添加文档”和“导入网页”必须是两个独立步骤，不再使用“文件或网页”混合描述。
- “添加文档”定位现有文件入口；“导入网页”定位现有网页入口。
- 某入口因现有套餐或响应式条件不可见时，向导应跳过可选步骤，不能卡死。

### 2.4 主页对话引导

- 仅在首次、空白的全局新对话页面弹出。
- 一个简洁步骤说明现有组合选择器可选择智能体、模型和思考强度，并说明部分高级模型需要升级、实际使用前会明确提示。
- 后续只提示现有输入区和发送按钮。
- 不增加新面板，不强制打开嵌套下拉框，不改变主页对话框任何视觉表现。

### 2.5 下拉框唯一权威

- 除主页新对话框内的选择器外，Lite 可见的语言、主题、模型、知识范围、记忆类型、Wiki 提取粒度、筛选等下拉框统一复用常规设置下拉框。
- 触发器高度、圆角、边框、内边距、字号、行高、箭头、焦点环必须一致。
- 弹层宽度、最大高度、圆角、阴影、内边距、滚动条、选项高度、选中背景、字重和对勾位置必须一致。
- 深浅主题均使用共享 token；不得出现白色触发器落在深色页面、双层边框、弹窗重叠或两个 popup 外壳。

### 2.6 账号菜单

- 用户名区域与“使用情况 / 升级套餐 / 设置”使用一致的行高、左右内边距和悬浮背景面积。
- 长用户名和邮箱必须在容器内收敛，不得把背景或内容撑出弹层。
- Lite 隐藏不支持的新手教程重放问号；Standard 保留。
- 小头像由蓝色改为中性黑色，并兼容深浅主题。
- 免费用户“升级套餐”恢复稳定的左侧图标，额度数据加载过程中也不能空白。

### 2.7 长期记忆页面

- Lite 可见文案不出现成员、工作区、空间管理员、每人上限等团队语义；统一改为对话、长期记忆、记忆上限等中性单用户表达。
- “仅显式记录 / 自动提炼”机械复用智能体编辑器已有分段控件样式。
- 模型和记忆类型下拉复用权威下拉框。
- 保留全部现有字段、默认值、权限、禁用关系、保存 payload 与校验；“两次挖掘的最小间隔”继续最小为 1 秒。
- 自动保存成功不再叠加 toast；失败仍显示一次明确错误；关闭设置时清理尚未执行的 debounce。
- 标题、说明、提示、行间距、控件宽度、高级设置、空态和深浅主题统一使用 Musuw 设置页现有结构。

### 2.8 知识库文档页按钮与筛选

- 顶部文件夹、三个筛选、视图切换、添加文档、导入网页使用同一高度、圆角、边框、字号、图标间距和 hover/focus 规则。
- “全部标签 / 全部类型 / 全部状态”三个筛选按钮使用同一组件契约，固定文案完整显示，禁止省略号。
- 三个筛选弹层使用权威下拉框的 popup 和 option 契约。
- “添加文档”是唯一反色主操作：浅色模式黑底白字，深色模式白底黑字；其余按钮为中性样式。

### 2.9 知识库主页与智能体主页

- 两页共享完全相同的页面背景、桌面/窄屏 padding、标题和副标题起点、顶部分隔线、内容起点与纵向节奏。
- 两页网格共享相同列数断点、列宽、间距和起点。
- 等价卡片共享最小高度、内边距、圆角、边框、标题/描述字号行高、底部分隔线和操作区基线。
- 同一视口快速切换两页时，共享锚点不得发生像素级跳动。
- 搜索等页面专属功能可以保留，但不能改变共享骨架。

### 2.10 删除确认弹窗

- 删除智能体和删除知识库复用一个基于现有 TDesign 的全局确认弹窗视觉契约。
- 删除页面局部的旧圆角、位置、隐藏标题和不匹配颜色覆盖。
- 标题、对象名、不可恢复说明、取消和红色确认按钮层级明确；按钮使用语义元素，键盘焦点可见。
- 深浅主题下背景、遮罩、文字、边框、中性按钮和危险按钮均符合全局 token。
- 原有取消、确认、删除和关闭 handler 各执行一次，业务行为不变。

### 2.11 多语言与一次性行为

- 中文、英文、俄文、韩文新增键必须同步，不能显示原始 i18n key。
- 新手引导继续使用现有按用户记录的完成状态；完成后返回页面不主动重复弹出。
- Lite 完成文案不再承诺可以从问号重放。

## 3. 明确不做

- 不重做主页新对话框。
- 不新增支付、套餐或额度逻辑。
- 不新增多租户、成员、共享、沙箱入口，也不删除 Standard 源码。
- 不新增组件库、状态系统、引导引擎、通知队列或设计 token 框架。
- 不为了视觉调整改变事件、字段、路由、API 和持久化语义。

## 4. 上线验收

- 目标契约测试、i18n 校验、类型检查、仓库已配置的静态检查和生产构建全部通过；当前前端未配置独立 lint 脚本，不虚构该项结果。
- 使用新 Lite 用户实际走通空知识库创建、默认命名、资料入口和首次新对话引导。
- 在相同桌面视口对比知识库/智能体页面锚点，并在窄屏复验布局。
- 所有涉及页面在浅色和深色模式检查下拉框、按钮、菜单、记忆页和删除弹窗。
- 确认 Standard 教程重放和上游协作能力仍存在，主页对话框视觉未发生变化。
- 合入 `main` 后等待 CI 与 staging 部署，再在部署版本重复关键链路。
