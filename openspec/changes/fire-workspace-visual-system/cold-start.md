# 火种冷启动优化

目标：减少手机首次进入知识库/对话时的真实下载与串行等待，保持原生身份、租户、能力检查和完整编辑功能。加载反馈必须区分仍在下载、离线和实际失败；不以假进度、自动刷新或缓存私有内容冒充完成。

已确认基线：2026-10-17 北京 fire-05，手机全新浏览器上下文，真实知识库卡片出现 5.957 秒，首屏约 2.3 MB；静态加载反馈 FCP 408 ms。前轮重复观测冷启动 6–8.3 秒，不能仅取最好一次。公网吞吐约 0.4 MB/s 是观测值，套餐带宽未核实。

方案遵循 Vue 官方代码拆分与腾讯 TDesign 官方按需导入：

- 移除三入口全量 TDesign 安装器，用官方构建期解析器注册各模板实际使用的控件；保留现有样式、图标、三个入口和本地图标隔离机制。
- 关闭的 Markdown 编辑器、检索设置不进入首页下载；第一次打开必须初始化当前库，编辑/预览/取消/再打开都保持原有行为。原控制器快照不改。
- 原生身份完成恢复后，独立部署元数据允许并行请求；原有身份、无租户引导、能力检查仍完成后才进入目标路由。
- 复用 HTML 内联加载区，保留主题与红色小图标；慢网仍显示加载，断网说明断网，真实模块错误可手动重试，不自动重载。

不做：SSR 框架迁移、Service Worker、账户内容离线缓存、新加载状态服务、假百分比、绕过认证、关闭 Skill/沙箱、变更模型和课程数据。服务器压缩和 HTTP/2 原本已启用。

2026-10-17 后续授权：修复实测首开依赖和重复请求，Wiki 正文不等待目录，然后北京发布和复测。验收需证明：

- 普通知识库/Wiki 首开不下载 Mermaid、Highlight、XLSX 等可选引擎；实际预览、代码、图表和表格导入仍能使用、失败能恢复。
- 文档首次仅一个原生列表请求，Wiki/graph 不下载隐藏文档列表；返回文档、过滤、目录导航及来源链接仍正常。
- Wiki 正文请求与索引/旁栏独立；目录慢或失败不阻挡正文。快速换页、切库、卸载的迟到响应不覆盖当前作品，默认索引、目录分页、编辑和图谱正常。
- 类型识别复用原生详情请求去重；父文档页/子Wiki页分别拥有当前视图的索引状态查询，保留后台索引反馈。
- 火种没有已存字体偏好时使用既有系统字体选项，保留用户保存的字体/字号、浅深色和其他产品原默认。
- 保留 fire-06 回滚，后端容器、运行配置和受保护业务数据不变。使用同一浏览器、直连和真实数据复测首页/Wiki冷启动及首次切入。

验收：类型检查与生产构建；按需产物检查；身份/租户回归；实际首次编辑器操作；桌面和390px窄屏；匿名登录、知识库、现有对话、Wiki、图谱；启动阶段断网/真实模块失败恢复；前后相同条件瀑布与缓存复测；北京原子发布和保留上一版本回滚。详细结果写入 docs/PETER_FIRE_LOADING_ACCEPTANCE.md。
