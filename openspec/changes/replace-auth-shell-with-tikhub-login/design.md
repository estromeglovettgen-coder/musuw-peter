## Context

生产未登录流量由 `auth/` React 壳承接；`weknora/frontend/src/views/auth/Login.vue` 会被路由守卫绕过。用户提供的 TikHub 生产包是其另一个自有项目，包内登录页由 `Login` 与 `AuthSplitLayout` 组成，但没有 source map。其身份 API、React runtime 与客服不属于 Musuw；左侧叙事及动效只作为视觉与行为参考，由 Musuw 在现有运行时边界内移植。

## Goals / Non-Goals

**Goals:**

- 复用已下载包中可观察到的 50/50 分栏、内容宽度、字体、表单层级、状态布局和响应式规则。
- 对登录、注册、邮箱验证码、忘记密码、重置密码、发送成功和加载状态使用同一视觉壳。
- 保留 Musuw 现有运行时行为与安全契约。

**Non-Goals:**

- 不引入 TikHub API、会话、路由、React runtime、客服或整包编译产物；动效只移植当前登录页实际需要的 Motion 与延迟加载 Three 实现。
- 不修改 Supabase、WeKnora OIDC、套餐续接、数据库或生产密钥。
- 不重新实现已存在的 Google、密码、OTP 或恢复流程。

## Decisions

### 1. 只移植视图结构，不运行编译后的 TikHub 应用

编译块依赖 TikHub 自己的入口运行时，直接嵌入会重复 React、身份状态和路由。Musuw 将在现有 `AuthApp` 中复现解包后可验证的 DOM 顺序和 CSS 尺寸，并复用包内 Geist 字体；所有事件继续调用 `AuthRuntime`。

### 2. 一个共享分栏壳覆盖全部认证状态

左侧是固定品牌叙事，右侧根据现有 screen 状态渲染表单、结果或加载提示。移动端隐藏左侧并显示紧凑品牌头。客服组件完全省略。

### 3. 替代身份入口位于表单后的分隔区

密码登录仍是主动作。Google 与邮箱验证码直接登录并排位于虚线分隔线后，分别调用现有 `startGoogle` 与 `useEmailCode`；注册和恢复模式不新增平行认证路径。

### 4. 黑白是主色，不改变语义状态色

按钮、焦点、文本和表面使用黑白中性色；错误和成功保留可访问的红/绿色语义反馈。暗色模式反转表面与文字，保持边界对比。

### 5. 左侧叙事保留动态层次与角色原色

桌面左栏使用黑色底面与跟随指针的高对比单色流体；流体实现延迟加载，避免阻塞认证表单。四个角色继续使用原始紫、深蓝、橙、黄色。中文固定前导语为“把资料转化为”，焦点词依次为“会”“思考的”“知识资产”；英文采用等价的前导语与三个焦点词。

## Risks / Trade-offs

- [编译包无 source map，无法逐行还原源组件] → 以下载包的 DOM、Tailwind utility 输出和截图作为独立依据，并用浏览器截图校验布局。
- [视觉替换误伤认证状态机] → 不改 runtime/provider 文件，增加源码边界与 SSR 入口顺序测试，并运行完整 97 项认证测试。
- [桌面双栏在小屏溢出] → 在 TikHub 相同的 `lg` 断点隐藏左栏，右栏保持 100% 且输入不小于可触控高度。
- [字体与动效增大构建] → 仅引入登录页实际使用的一个 Geist 变量字体；流体代码独立分块并延迟加载，不带入 TikHub 应用运行时。

## Migration Plan

1. 先添加失败的视图契约测试。
2. 修改 `AuthApp` 视图结构与 CSS，拷贝最少字体资产。
3. 运行 auth 单测、类型检查、构建与本地浏览器检查。
4. 发布仍沿用现有 auth shell 构建/部署路径；回滚只需恢复 auth 视图、样式和字体，不涉及数据迁移。

无；用户已确认参考项目归其所有，并明确排除客服组件。
